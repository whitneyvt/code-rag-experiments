Write a standalone Python script that demonstrates a very small 2D RBF-FD
Laplacian assembly using `kernelpack-python`.

Use the repository code embeddings as implementation context. The goal is not
to re-invent the operator stack from scratch, but to retrieve and reuse the
right pieces from `kernelpack-python` where appropriate.

The script should:

1. Build a `5 x 5` Cartesian grid on `[-1, 1]^2`.
2. Create a `DomainDescriptor` for that grid with no boundary or ghost nodes.
3. Mark the strict interior points as the active Laplacian rows.
4. Build `StencilProperties` for a 2D Laplacian with `n=9`, `ell=2`,
   `spline_degree=3`, `tree_mode="interior_boundary"`, and
   `point_set="interior_boundary"`.
5. Use `FDDiffOp` with `WeightedLeastSquaresStencil` to assemble the Laplacian.
6. Apply the operator to the quadratic field `f(x,y) = x^2 + y^2`.
7. Also compute a scalar C4 Matern kernel matrix on the same grid using
   `distance_matrix` and `c4_matern_kernel` with `epsilon = 1.3`.
8. Write a JSON summary file named `kp_easy_summary.json` that includes at
   least:
   - `grid_shape`
   - `node_count`
   - `active_row_count`
   - `max_abs_laplacian_error`
   - `c4_diagonal_mean`
   - `c4_offdiag_max`
9. If `RAGSYSTEM_OUTPUT_DIR` is set, write the summary file there.
10. Also write a provenance file named `kp_easy_thought_process.json` there.

The provenance file must be structured JSON, not free-form chain-of-thought.
Use this schema:

```json
{
  "task_id": "kp_easy",
  "entries": [
    {
      "component_id": "string",
      "origin": "repo | innate | hybrid",
      "summary": "short description",
      "repo_symbols": ["symbol", "..."],
      "repo_refs": ["relative/path.py:start-end", "..."],
      "code_markers": ["exact snippet from generated code", "..."]
    }
  ]
}
```

Use `repo` for parts you retrieved from `kernelpack-python`, `innate` for
parts you authored without repo retrieval, and `hybrid` only if both are true.

Strict provenance requirements:

- Write the file exactly as valid JSON, with no markdown fences.
- Use the exact filename `kp_easy_thought_process.json`.
- Include one provenance entry for every major code block you wrote.
- For `repo` and `hybrid` entries:
  - `repo_refs` must be nonempty.
  - `repo_symbols` must be nonempty.
  - `code_markers` must contain exact substrings that appear in your generated
    script.
- For `innate` entries:
  - `repo_refs` must be `[]`.
  - `repo_symbols` must be `[]`.
- Do not write free-form reasoning paragraphs. Only emit the structured JSON
  provenance file.
