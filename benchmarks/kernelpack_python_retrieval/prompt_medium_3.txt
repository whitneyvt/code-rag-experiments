Write a standalone Python driver that solves a mixed-boundary Poisson problem
on a smooth closed curve using `kernelpack-python`.

Use the repository code embeddings as implementation context. The goal is to
retrieve the geometry construction, domain-generation workflow, and
`PoissonSolver` usage pattern from `kernelpack-python`, then implement a clear
driver around those pieces.

The script should:

1. Define a nontrivial exact solution `u(x,y)`.
2. Define the forcing term that matches the exact solution.
3. Define a boundary callback that combines nonzero Neumann and Dirichlet
   coefficients, so the mixed-boundary branch is exercised.
4. Build a smooth closed curve from sampled boundary points.
5. Build a smooth geometry with `EmbeddedSurface`,
   `set_data_sites`, `build_closed_geometric_model_ps`, and
   `build_level_set_from_geometric_model`.
6. Use `DomainNodeGenerator.build_domain_descriptor_from_geometry` to create a
   2D domain with boundary refinement enabled.
7. Construct a `PoissonSolver` with `lap_assembler="fd"`,
   `bc_assembler="fd"`, `lap_stencil="rbf"`, and `bc_stencil="rbf"`.
8. Call `init(domain, xi)` and solve the mixed-boundary problem.
9. Compute a mean-aligned error before reporting final norms.
10. Write a JSON summary file named `kp_medium_3_summary.json` with at least:
    - `h`
    - `n_physical`
    - `num_boundary_nodes`
    - `linf`
    - `l2`
    - `used_nullspace_augmentation`
11. If `RAGSYSTEM_OUTPUT_DIR` is set, write the summary file there.
12. Also write a provenance file named
    `kp_medium_3_thought_process.json` there.

The provenance file must be structured JSON, not free-form chain-of-thought.
Use this schema:

```json
{
  "task_id": "kp_medium_3",
  "entries": [
    {
      "component_id": "string",

    }

```

Use `repo` for parts you retrieved from `kernelpack-python`, `innate` for
parts you authored without repo retrieval, and `hybrid` only if both are true.

Strict provenance requirements:

- Write the file exactly as valid JSON, with no markdown fences.
- Use the exact filename `kp_medium_3_thought_process.json`.
- Include one provenance entry for every major code block you wrote.
- For `repo` and `hybrid` entries:
  - `repo_refs` must be nonempty.
