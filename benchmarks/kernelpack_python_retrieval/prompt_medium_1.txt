Write a standalone Python script that solves one small 2D pure-Neumann Poisson
problem on a smooth circular domain using `kernelpack-python`.

Use the repository code embeddings as implementation context. The main purpose
is to retrieve the correct driver structure from `kernelpack-python`, not to
invent a new solver interface.

The script should:

1. Define the exact solution `u(x,y) = exp(x + y)`.
2. Define the forcing `f(x,y) = -2 exp(x + y)`.
3. Define the Neumann boundary flux from the gradient of the exact solution.
4. Build circle data sites with `t = linspace(0, 2*pi, n, endpoint=False)` and
   points `(cos(t), sin(t))`.
5. Build a smooth geometry with `EmbeddedSurface`,
   `set_data_sites`, `build_closed_geometric_model_ps`, and
   `build_level_set_from_geometric_model`.
6. Use `DomainNodeGenerator.build_domain_descriptor_from_geometry` to create a
   2D domain with `h = 0.14`, `seed = 17`, and `strip_count = 5`.
7. Construct a `PoissonSolver` with `lap_assembler="fd"`,
   `bc_assembler="fd"`, `lap_stencil="rbf"`, and `bc_stencil="rbf"`.
8. Call `init(domain, 2)` and solve the pure-Neumann problem.
9. Compute a mean-aligned error by subtracting the mean of
   `u_num - u_true` before reporting the final norms.
10. Write a JSON summary file named `kp_medium_summary.json` with at least:
    - `h`
    - `n_physical`
    - `linf`
    - `l2`
    - `used_nullspace_augmentation`
11. If `RAGSYSTEM_OUTPUT_DIR` is set, write the summary file there.
12. Also write a provenance file named `kp_medium_thought_process.json` there.

The provenance file must be structured JSON, not free-form chain-of-thought.
Use this schema:

```json
{
  "task_id": "kp_medium",
  "entries": [
    {
      "component_id": "string",
      "origin": "repo | innate | hybrid",

      "repo_refs": ["relative/path.py:start-end", "..."],
      "code_markers": ["exact snippet from generated code", "..."]
    }
  ]
}
```

Use `repo` for parts you retrieved from `kernelpack-python`, `innate` for
parts you authored without repo retrieval, and `hybrid` only if both are true.

Strict provenance requirements:

- Write the file exactly as valid JSON, with no markdown fences.
- Use the exact filename `kp_medium_thought_process.json`.
- Include one provenance entry for every major code block you wrote.
- For `repo` and `hybrid` entries:
  - `repo_refs` must be nonempty.
  - `repo_symbols` must be nonempty.
  - `code_markers` must contain exact substrings that appear in your generated
    script.
- For `innate` entries:
  - `repo_refs` must be `[]`.
  - `repo_symbols` must be `[]`.
- Do not write free-form reasoning paragraphs. Only emit the structured JSON
  provenance file.
